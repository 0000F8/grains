# Grains Identity Spec — `grains-identity/0.1`

Status: v1 normative. Diverges deliberately from `docs/architecture.html`
(which shows Ed25519 `did:key:z6Mk…` examples): Grains uses **secp256k1**
everywhere, because AWS KMS supports sign-only custody for `ECC_SECG_P256K1`
(the private key never exists outside KMS) and the same curve signs EVM
transactions — one key type for identity, receipts, and the wallet.

## 1. Root key

- Curve: secp256k1. The root keypair IS the agent's identity.
- Hosted agents: the private key is a KMS asymmetric key (`ECC_SECG_P256K1`,
  usage SIGN_VERIFY); all signatures are produced via `kms:Sign`. The key is
  never exported or unwrapped.
- Self-hosted agents (SDK): any secp256k1 keystore works; the formats below
  are custody-agnostic.

## 2. DID encoding (`did:key`)

`did = "did:key:" + multibase(base58btc, varint(0xe7) || compressed_pubkey)`

- `varint(0xe7)` is the two bytes `0xe7 0x01` (multicodec `secp256k1-pub`).
- `compressed_pubkey` is the 33-byte SEC1 compressed point.
- base58btc uses the Bitcoin alphabet with multibase prefix `z`.
- Resulting DIDs start `did:key:zQ3s`.

## 3. EVM address derivation

`address = "0x" + hex(keccak256(uncompressed_pubkey[1:])[-20:])`

- `uncompressed_pubkey` is the 65-byte SEC1 point; drop the leading `0x04`.
- Addresses are lowercase hex in canonical documents. EIP-55 checksum casing
  is a display concern only.

## 4. Canonical JSON (signing input)

All Grains signatures are computed over **canonical JSON bytes**:

1. UTF-8, keys sorted lexicographically at every level, separators `,` and
   `:` (no whitespace).
2. Numbers MUST be integers. Monetary and other decimal values are strings.
   Floats are forbidden in any signed document.
3. The `sig` field is removed before canonicalization.

(Equivalent to Python `json.dumps(doc, sort_keys=True,
separators=(",", ":"), ensure_ascii=False).encode("utf-8")` after deleting
`sig`; compatible with RFC 8785 for the value domain allowed here.)

## 5. Signature

- Algorithm `ES256K`: ECDSA over secp256k1, message digest SHA-256 of the
  canonical bytes, deterministic nonce per RFC 6979, **low-s normalized**
  (s ≤ n/2).
- Encoding: `base64url(r || s)` — 64 bytes, no padding.
- Signature object: `{"alg": "ES256K", "kid": "<did of signer>",
  "value": "<base64url>"}`.

## 6. Identity document

```json
{
  "spec": "grains-identity/0.1",
  "did": "did:key:zQ3s…",
  "version": 1,
  "created_at": "2026-08-23T00:00:00Z",
  "bindings": [
    {"type": "rail", "rail": "evm:base-sepolia", "address": "0x…"},
    {"type": "venue", "venue": "grains", "endpoint": "agents.grains.run/<name>"}
  ],
  "sig": {"alg": "ES256K", "kid": "did:key:zQ3s…", "value": "…"}
}
```

- `sig.kid` MUST equal `did` (self-signed by the root key).
- A rail binding's `address` MUST derive from the same public key when the
  rail shares the root key (v1 hosted default); otherwise the binding is a
  claim vouched for only by the root signature.
- Re-issue with `version + 1` to rotate bindings; higher version supersedes.
- Timestamps: ISO 8601 UTC with `Z` suffix, second precision.

## 7. Verification procedure

1. Parse `did` → compressed public key (reverse of §2).
2. Canonicalize the document minus `sig` (§4); verify `sig.value` (§5)
   against that public key. Reject if `sig.kid != did`.
3. For each rail binding claiming the root key, recompute §3 and compare.

## 8. Test vectors

Generated by `spec/tools/generate_vectors.py` into `spec/vectors/` from a
fixed, publicly-known test key (never use it for anything real):

- `keys.json` — test private key (hex), compressed/uncompressed public key,
  DID, EVM address.
- `identity_doc.json` — a complete signed identity document.

`spec/tools/test_vectors.py` MUST pass: derivations reproduce, signatures
verify, and any single-byte tamper fails verification.
